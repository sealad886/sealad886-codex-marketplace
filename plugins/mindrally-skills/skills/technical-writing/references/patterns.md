# Technical explanations and tutorials: implementation decisions

Load this reference when implementing the relevant patterns; select the subset
that matches the installed framework, target, and requested behavior.

- Choose tutorial, how-to, reference, or explanation structure from the reader’s need rather than forcing every document into a complete implementation tutorial.

- Use lists for sequences/comparisons and paragraphs for connected reasoning; a blanket no-bullets rule can make procedures harder to follow.

- Examples should be minimal but complete for the promised behavior; label omitted integration code and placeholders honestly.

- Tie APIs and commands to supported versions and real file locations; do not invent architecture or dependencies to make prose look substantial.

- Distinguish verified outcomes from assumptions, proposals, and unexecuted instructions. Do not promise correctness or runtime behavior from editing alone.

- Use meaningful headings, descriptive links, language-tagged code fences, and text alternatives for necessary visuals.

- Explain why consequential decisions matter; include tradeoffs or failure modes when the reader needs them, without obligatory pros/cons sections.

- Keep private data, credentials, and internal paths out of public examples; publishing and external messages need task authority.
