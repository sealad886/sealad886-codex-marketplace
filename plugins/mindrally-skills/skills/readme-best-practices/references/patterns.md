# README accuracy and usefulness: implementation decisions

Load this reference when implementing the relevant patterns; select the subset
that matches the installed framework, target, and requested behavior.

- Choose section order for the reader: an example may precede installation if understandable, while hardware or credential prerequisites may need to come first.

- Do not promise a universal 30-second setup or fixed first-five-line example; record actual prerequisites and measured constraints.

- Use commands matching the project’s package manager and supported versions; label placeholders clearly and keep secrets out of examples.

- Use badges only for accurate maintained facts and target the correct branch or release.

- Link detailed API documentation rather than duplicating it; keep configuration names, defaults, and failure messages aligned with implementation.

- Use repository-relative asset and file links when appropriate, with descriptive alt text and readable heading hierarchy.

- Verify shell snippets in a safe disposable environment when practical; do not run deployment or destructive examples as a documentation check.

- Use tables or lists according to information shape; author cards, badges, and marketing hooks are optional presentation choices.
