# Native release configuration examples

These inactive files complement the publisher workflows. Copy the selected files into the **target project**, review identifiers, and use that project's native lock/wrapper tooling. Do not copy every configuration or introduce a second version source.

| Example | Destination and supplied contract | Local validation |
|---|---|---|
| [GoReleaser](goreleaser.yaml.template) | `.goreleaser.yaml` beside the [Go module](../../examples/go/go.mod). Builds six platform/architecture combinations, embeds `main.version`, creates tarballs and `checksums.txt`, fills an existing draft without replacing it. | `goreleaser check`; in a disposable Git checkout `goreleaser release --snapshot --clean --skip=publish`. Use v2.8.2 to match the workflow. |
| [Maven distribution](maven-distribution.xml.template) | Merge under the root element of the [Maven example](../../examples/jvm/pom.xml); replace the example repository with the authorized lower-case owner/repository. The `github` ID matches setup-java's generated settings. | Native wrapper `help:effective-pom` and `verify`. Inspect the effective distribution URL and flattened release POM before `deploy`. |
| [Gradle build](gradle-build.gradle.kts.template) | `build.gradle.kts` for the [Gradle example](../../examples/jvm/gradle/build.gradle.kts); preserve `group`/`version` in its existing properties file. Reads Actions credentials only for publishing and exposes the publisher's version check. | Native wrapper `check printReleaseVersion publishToMavenLocal`; inspect generated Maven POM/version in the disposable local repository. |
| [Rust toolchain](rust-toolchain.toml.template) | `rust-toolchain.toml` beside the [Rust workspace](../../examples/rust/Cargo.toml). Exact Rust version, minimum profile and explicit components. | `rustup show active-toolchain`, `cargo metadata --locked --no-deps --format-version 1`, `cargo test --workspace --locked`. |
| [Rust release order](rust-release-order.txt.template) | `release-order.txt` in the same workspace. Uses the example's real package names, core before dependent CLI. | The Rust publisher compares every publishable member, version and dependency order before publishing. |

The Go publisher requires Release Please to create a draft release; its verified draft SHA identifies the target for already-authorized tag creation only when the tag is absent. GoReleaser leaves the release a draft until the workflow verifies expected assets and explicitly publishes it. Do not pair this draft configuration with a coordinator configured to finalize a release before assets exist. Full GoReleaser field names above were checked against [v2.8.2 configuration types](https://github.com/goreleaser/goreleaser/blob/v2.8.2/pkg/config/config.go).

Generate and commit Maven/Gradle wrappers using the target project's chosen native versions and checksum validation; wrappers are project tooling, not produced by this plugin. The Gradle workflow requires a nonempty wrapper `distributionSha256Sum`. Validate Maven wrapper distribution/checksum under the repository's normal dependency policy. A missing wrapper is a setup prerequisite, not permission to run an unpinned global replacement.

These examples do not configure Maven Central signing/staging. GitHub Packages setup is described in [Maven registry documentation](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-apache-maven-registry) and [Gradle registry documentation](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-gradle-registry). Native configuration was reviewed as reference content; hosted registry publication remains unverified.
