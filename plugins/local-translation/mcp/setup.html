Set up Local Translation

Connect the plugin to your running local Index-Translate model in oMLX or a vLLM-compatible engine. These settings work when you open Codex or Copilot normally, without editing MCP settings or restarting the app.

The engine must expose model listing and chat tokenization, including POST /tokenize. Compatibility depends on the installed engine version. This page checks the connection and tokenizer without generating a translation or downloading models.

Workspace and engine

An existing folder containing the files you authorize the plugin to read. Job and review records are saved beneath this folder. Enter its full local path.

Use the port shown in your oMLX or runner settings, with /v1 at the end. Replace localhost with 127.0.0.1. Remote endpoints and hostnames are not accepted.

Must match an entry returned by the engine’s /v1/models endpoint. Check the runner you actually started.

Enter metadata you verified in your deployment. A successful connection cannot attest the model’s files or training, and the plugin does not invent these values.

One locale=language label per line. Include the source and every target locale. Register only the languages you intend to use and qualify.

Optional engine authentication

Enter a key only in this local browser page, never in chat. If saved, it is stored as plaintext in your private user settings file (0600 on POSIX); it is not stored in Keychain. It is never returned to the assistant or prefilled here. Other processes running as your user can read this file.

Generation limits and timeouts

Use limits supported by your actual engine. The context window must fit both the tokenized prompt and output. Changing deployment settings requires a replacement translation job.

Loading your local settings…

This private page expires after ten minutes and closes its local server after saving. Settings stay outside the plugin installation and survive plugin updates. Existing settings are preserved when a check or save fails.
