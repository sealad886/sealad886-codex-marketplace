# Interaction and correction protocol

Use role-specific working methods from the [role directory](roles.md) and the
common [expert contract](expert-contract.md). The coordinator retains one brief,
assignment map, decision log and release record. The runtime owns its immutable
inputs and supported job/query/review state for its temporary MCP session;
do not build a second job database. Retain required returned content and review
evidence through the calling agent's authorized route before the server exits.
Job IDs do not survive restart.

For Index-family model work, use the canonical
[common input guide](index-inputs.md) and its selected profile reference. The
coordinator assigns that conditional reading; role handoffs supply approved
requirements, terminology and owner context while the shared recipes own native
formats, decoding guidance and existing-MCP examples.

## Dispatch and capacity

Inspect actual host creation, messaging and follow-up APIs and available slots.
Read the assigned installed role skill, acknowledge its remit, and return real
work under the host agent ID. Directly invoked specialists can use the same
contract without starting the coordinator or an unnecessary team.

Resolve skill paths from the installed package, not a development checkout.
Pass the role skill and expert-contract paths explicitly; never assume a generic
agent acquired the remit from a role label. Host agent types and plugin skill IDs
are separate namespaces. If no delegation API exists, report that gap rather
than fabricating agent execution or silently replacing the requested team.

Queue scarce slots and local inference capacity. Load compatible skills on one
agent where independence is unnecessary. For the same material, authors and
independent bilingual revisers must have different actual agent IDs. Different
actor strings alone do not satisfy this requirement. The coordinator grants one
state-changing job turn at a time, including status calls that can retire stale
delivery readiness. Parallel research must not race shared artifacts.

## Required exchanges

| Exchange | Required contribution and response |
| --- | --- |
| Preparation | Engineer reports source coverage and extraction risks; terminologist and subject reviewer exchange concept evidence and proposed usage; content liaison seeks unresolved human intent decisions |
| Draft handoff | Translator supplies candidate identity, coverage, self-check, research and uncertainties; reviser acknowledges the exact source/target/context it will compare |
| Revision dialogue | Reviser states location, classification, severity, source evidence and remedy; translator returns a correction or reasoned disagreement tied to the issue |
| Adjudication | Language lead settles expression within brief; domain specialist supplies concept evidence; human content owner decides source intent or changed requirements; coordinator broadcasts the attributed decision |
| Production feedback | Editor, proofreader, captioner or engineer names the actual artifact and defect; substantive wording proposals return to the linguist and current-scope bilingual comparison |
| Release reconciliation | Quality evaluator reports rubric and actual coverage; release preparation reconciles exact artifacts and missing work; coordinator presents the candidate to the actual human release owner |

Send directly through the host's actual messaging facility when available.
Otherwise the coordinator relays attributed findings and responses and records
that relay. Do not claim direct conversation when only a relay occurred. External
people/services still need applicable user authorization; team instructions do
not authorize unsolicited messages or content disclosure.

No-findings reports must identify actual inspected coverage and limits. Do not
invent errors or objections to meet a conversation quota. Conversely, an issue
does not close merely because another agent says “approved”: retain its response,
evidence, decision owner and required recheck.

## Bounded resolution

Classify each issue as target defect, shared-input/source defect, valid
alternative, new requirement, or unavailable evidence/tool capability. Within a
defect, identify its meaning, terminology, action, fluency, locale, structural or
presentation category. Use the common consequence-based severity and issue record.

Allow two correction rounds per issue by default, then escalate concrete competing
evidence to the owner who can decide. Never resolve meaning by vote or hide a
blocker to meet a deadline. Continue unrelated work while the affected locale or
stage is blocked. Ordinary terminology research precedes questions already
answerable by approved resources.

## Change propagation

A target repair creates a new candidate digest and invalidates prior target
review. A shared query changes `context_revision`, invalidating stored and
in-flight review based on the previous context even if text is unchanged.
Revisers must actually inspect the new context before submitting its revision.
Query answers are not automatically included in inference prompts or used to
regenerate drafts. Require explicit incorporation into the next compatible
caller-owned message, a bounded correction with current revision, or a replacement
workbench job with reconciled approved brief/glossary for a new generation.

A source, brief, glossary, locale or configuration change creates a replacement
job. Record its predecessor and reason, supersede the old candidate in the
project record, identify every dependent occurrence/locale/product and repeat
affected work. Never transplant approval to different bytes or contexts.
Diagnose upstream source defects at the shared input, not as repeated translator
errors. Retain returned prior artifacts and decision evidence through the
caller's authorized route when they are needed beyond the temporary session.
