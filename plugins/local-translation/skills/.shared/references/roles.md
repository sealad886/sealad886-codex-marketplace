# Role skills and decision rights

The supplied *Professional Translation Services* whitepaper describes sixteen
functions, not a mandatory staffing count (pp. 4–5). Each function has an explicit
skill below. Four more named responsibilities in its document and AV workflows
also have separate skills. The coordinator commissions the necessary coverage;
twenty installed skills do not require twenty simultaneous agents.

Each specialist reads its own skill and the [expert contract](expert-contract.md).
Skills supply procedures, discriminating questions and evidence standards to the
host agent; they do not confer human qualification, legal authority or new tools.

| Whitepaper function | Installed role skill and work product | Decision boundary |
| --- | --- | --- |
| Client sponsor/localization owner | [Client intake](../../client-intake/SKILL.md): purpose, audience, locale and acceptance proposal | Actual human sponsor confirms scope, disclosure, changes and acceptance authority |
| Client content/creative owner | [Content liaison](../../content-liaison/SKILL.md): researched source queries and attributed answers | Actual content owner decides facts, intended meaning and creative departures |
| Account/commercial manager | [Commercial scope](../../commercial-scope/SKILL.md): deliverables, stages, estimates and exclusions | No agent agrees contracts, prices, procurement or external commitments |
| Project manager | [Translation project](../../translation-project/SKILL.md): assignments, dependencies, query routing and release evidence | Coordinates evidence without replacing linguistic or human decision ownership |
| Vendor/resource manager | [Resource planning](../../resource-planning/SKILL.md): competence evidence, capacity and independence plan | Model or agent identity is not a qualification certificate |
| Document/localization engineer | [Localization engineering](../../localization-engineering/SKILL.md): complete supported working units, protected tokens and source coverage | Text/segment runtime does not supply arbitrary extraction or reconstruction |
| Translator/audiovisual translator | [Locale translation](../../locale-translation/SKILL.md): target proposals, research, self-check and queries | Cannot amend source facts or independently revise its own material |
| Transcriber/source-language proofer | [Source transcription](../../source-transcription/SKILL.md): recording-verified transcript and uncertainty record | Requires exact recording and suitable listening/transcription tools |
| Spotter/template editor | [Subtitle spotting](../../subtitle-spotting/SKILL.md): stable events, timing, segmentation and context | Requires actual media/timing tools; cannot invent timecodes from text |
| Terminologist/language lead | [Terminology management](../../terminology-management/SKILL.md): concepts, provenance, usage conditions and linguistic adjudication | Domain evidence identifies the concept; source intent belongs to the content owner |
| Independent bilingual reviser | [Bilingual revision](../../bilingual-revision/SKILL.md): source-comparison findings, reasons and current-scope recommendation | Different actual agent from the material's authors; AI revision remains AI revision |
| Subject/client-market reviewer | [Subject review](../../subject-review/SKILL.md): domain relationships, organizational usage and audience concerns | Target-only review does not establish source fidelity; meaning changes return to comparison |
| Caption/SDH specialist | [Accessibility captioning](../../accessibility-captioning/SKILL.md): commissioned speaker/sound/accessibility coverage | Needs proper audio/picture and profile; dialogue translation alone is insufficient |
| DTP specialist/subtitle engineer | [Production engineering](../../production-engineering/SKILL.md): actual output structure, rendering, encoding and delivery-profile evidence | Substantive shortening needs linguistic agreement; missing production tools remain a gap |
| Quality evaluator/quality lead | [Quality evaluation](../../quality-evaluation/SKILL.md): rubric, coverage, adjudicated findings and corrective actions | Sampling and model scores cannot stand in for full review or acceptance |
| Release owner | [Release preparation](../../release-preparation/SKILL.md): current manifest, completed checks and unresolved limits | Actual human release owner accepts identified files and authorizes delivery |

The workflow's additional named responsibilities have their own remits:

| Responsibility | Installed role skill and work product | Decision boundary |
| --- | --- | --- |
| Target-language editor (pp. 8–9) | [Target-language editing](../../target-language-editing/SKILL.md): coherence, register, readability and house-style proposals | Target-only editing cannot replace bilingual revision; material changes return for comparison |
| Final proofreader (p. 9) | [Final proofreading](../../final-proofreading/SKILL.md): findings against actual rendered/exported output | Working-text approval cannot establish final presentation or accessibility |
| Media coordinator (p. 10) | [Media coordination](../../media-coordination/SKILL.md): exact cut/audio/locale/track matrix and dependencies | Does not infer recording or track identity from a filename alone |
| Conformer (pp. 12–13) | [Media conformance](../../media-conformance/SKILL.md): changed intervals, time mapping and affected-track rechecks | Constant offsets do not repair inserted/reordered content; exact final media is required |

Compatible functions may be combined after their skills are loaded and scopes
recorded. Translator and independent bilingual reviser remain different actual
agents for the same material. Source/audio proofing, target-language editing,
bilingual revision, technical checks and quality evaluation are different kinds
of evidence; one approval cannot silently substitute for another.

Host skill invocation can use the discovered namespace, such as
`$local-translation:bilingual-revision`. For delegation, resolve and pass the
actual installed skill file path as described in the coordinator and assignment
template. A skill ID is not a promise that a host has a same-named agent type.
